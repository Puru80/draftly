# Draftly — AI-Powered Email Drafting Assistant

Draftly is an intelligent email drafting application that integrates with **Google Gmail** and **Google Gemini AI** to automatically generate context-aware email replies in a user's personal writing style. It syncs incoming email threads, generates AI drafts with configurable tones, and sends replies with proper threading — all through a REST API consumed by a React frontend.

---

## Design Decisions

### 1. Session-Based OAuth2 (No JWT)

The application relies on **Spring Security's built-in OAuth2 client** with session-based authentication. After the user authenticates with Google, Spring Security manages the session, and the JSESSIONID cookie is used for subsequent API calls. This avoids the complexity of issuing and validating local JWTs while leveraging Google as the identity provider.

- The `OAuth2SuccessHandler` redirects the browser to the frontend with `?login=success&email=<email>`, letting the React app detect the authenticated session.
- All API requests must include credentials (`credentials: 'include'` on fetch / `withCredentials: true` on axios).

### 2. Encrypted Refresh Token Storage

Google's OAuth2 refresh token (which never expires unless revoked) is **encrypted with AES-256** before being stored in the database. The encryption key is loaded from `ENCRYPTION_SECRET_KEY` and must be kept secret. This ensures that a database breach does not expose raw refresh tokens that could grant persistent Gmail access.

### 3. On-Demand Gmail API Token Exchange

Each call to the Gmail API performs a **fresh OAuth2 token exchange** from the stored refresh token. While this adds latency per request, it avoids the complexity of access token expiry management and caching. This is a deliberate simplicity trade-off that can be optimized later with token caching (`expires_in` is typically 3600 seconds).

### 4. Few-Shot Style Mimicry for AI Drafts

When generating a draft, the `AiDraftEngineService` fetches the user's **3 most recent sent emails** from Gmail and includes them as writing style samples in the system prompt to Gemini. This allows the AI to mimic the user's greeting preferences, vocabulary level, sentence structure, and formatting habits without requiring a separate training step.

### 5. Idempotent Email Dispatch

The send endpoint requires an **`X-Idempotency-Key`** header (typically a UUID generated by the client). The `IdempotentDispatcherService` checks both the draft's status (`APPROVED` = already sent) and the stored idempotency key (duplicate retry) before sending. Combined with a database `UNIQUE` constraint on `drafts.idempotency_key`, this guarantees that a reply is never sent more than once even if the client retries.

### 6. Scheduled Inbox Polling

An `EmailSyncScheduler` polls the Gmail API every **5 minutes** per user, fetching up to 10 unread messages and creating `EmailThread` records for any new threads. This is a simple polling approach — no webhook/push notifications, no pagination. Draft auto-generation on new thread creation is marked as a TODO for future implementation.

### 7. MIME Threading Continuity

When sending replies, the `IdempotentDispatcherService` extracts the parent message's `Message-ID` and `References` headers and sets `In-Reply-To` and `References` on the outbound MIME message. This ensures the reply nests correctly within the Gmail thread, preserving conversation continuity in the client.

### Draft Lifecycle

```
EmailSyncScheduler (every 5 min)
  └── Fetch unread messages
  └── Create EmailThread records

GET /api/v1/threads                   Browse threads
GET /api/v1/threads/{id}              View thread detail

POST /api/v1/threads/{id}/generate-draft   Generate AI draft
  └── Fetch latest message body from Gmail
  └── Fetch user's sent history (style samples)
  └── Call Gemini AI with system prompt
  └── Save EmailDraft (status = PENDING)
       │
       ├── PUT /api/v1/drafts/{id}/body        Edit draft body -> EDITED
       │
       ├── POST /api/v1/drafts/{id}/tone       Regenerate with new tone
       │      Old draft -> REJECTED
       │      New draft -> PENDING
       │
       └── POST /api/v1/drafts/{id}/send       Send reply via Gmail
              X-Idempotency-Key header
              Build MIME with threading headers
              Send -> status = APPROVED
```

## API Reference

All endpoints require an authenticated OAuth2 session. The React frontend must include credentials with every request.

### Threads (`/api/v1/threads`)

| Method | Path | Description |
|--------|------|-------------|
| `GET` | `/api/v1/threads` | List all threads for the authenticated user, sorted by `lastSynchronizedAt` descending |
| `GET` | `/api/v1/threads/{id}` | Get a single thread with all its messages (sorted newest-first) |
| `POST` | `/api/v1/threads/{id}/generate-draft` | Generate an AI draft reply for the thread |

**`GET /api/v1/threads/{id}` response:**
```json
{
  "id": 1,
  "gmailThreadId": "191234567890abcdef",
  "subject": "Meeting Tomorrow",
  "lastSynchronizedAt": "2025-05-31T10:30:00Z",
  "messages": [
    {
      "messageId": "1912345abc",
      "from": "Alice <alice@example.com>",
      "to": "Bob <bob@example.com>",
      "subject": "Meeting Tomorrow",
      "date": "Fri, 30 May 2025 14:00:00 +0000",
      "snippet": "Let's meet tomorrow at 10am...",
      "body": "Base64url-decoded email body text"
    }
  ]
}
```

**`POST /api/v1/threads/{id}/generate-draft` request:**
```json
{ "tone": "CONCISE" }
```

**Response:** `DraftResponseDto` (see below)

### Drafts (`/api/v1/drafts`)

| Method | Path | Description |
|--------|------|-------------|
| `GET` | `/api/v1/drafts/pending` | List all pending drafts |
| `PUT` | `/api/v1/drafts/{id}/body` | Edit draft body content (status -> `EDITED`) |
| `POST` | `/api/v1/drafts/{id}/tone` | Regenerate draft with a different tone |
| `POST` | `/api/v1/drafts/{id}/send` | Send the draft as a reply via Gmail |

**`POST /api/v1/drafts/{id}/send` header:**
```
X-Idempotency-Key: <client-generated-uuid>
```

Returns `409 Conflict` if the draft was already sent or the idempotency key is reused.

## Setup Instructions

### Prerequisites

- **Java 17+** and **Maven**
- **PostgreSQL 14+** running on `localhost:5432`
- A **Google Cloud Project** with the Gmail API enabled
- A **Gemini API key** (from Google AI Studio)

### 1. Clone and Configure

```bash
git clone <repo-url>
cd draftly
```

### 2. Database

Create the database:

```bash
createdb draftly
```

The schema is managed via `src/main/resources/schema.sql`. Spring Boot is configured with `ddl-auto=validate`, so the schema must be applied manually or via a migration tool.

Apply the schema:

```bash
psql -d draftly -f src/main/resources/schema.sql
```

### 3. Environment Variables

Create or edit `.env` in the project root:

```env
GOOGLE_CLIENT_ID=your-google-oauth2-client-id
GOOGLE_CLIENT_SECRET=your-google-oauth2-client-secret
GEMINI_API_KEY=your-gemini-api-key
ENCRYPTION_SECRET_KEY=64-hex-characters-32-bytes-for-aes-256
DB_USERNAME=postgres
DB_PASSWORD=password
```

**Generating the encryption key:**
```bash
openssl rand -hex 32
```

**Google OAuth2 configuration:**
1. Go to [Google Cloud Console](https://console.cloud.google.com)
2. Create a project and enable the **Gmail API**
3. Configure the OAuth consent screen with scopes: `userinfo.email`, `gmail.readonly`, `gmail.compose`, `gmail.modify`
4. Create an OAuth2 client ID of type **Web application**
5. Set authorized redirect URI to: `http://localhost:8080/login/oauth2/code/google`

### 4. Build and Run

```bash
./mvnw spring-boot:run
```

The server starts on `http://localhost:8080`.

### 5. Frontend

The backend expects a React frontend at `http://localhost:3000`. After OAuth login, the user is redirected to:

```
http://localhost:3000/dashboard?login=success&email=<user-email>
```

The React app should:
- Parse the `login` and `email` query parameters from the redirect
- Include credentials (`credentials: 'include'`) on all API requests to `http://localhost:8080`
- Pass `X-Idempotency-Key` (a UUID) when calling the send endpoint
